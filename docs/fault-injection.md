# Fault injection (Этап 8)

Стенд: compose-кластер (см. README «Целевая система»), нагрузка `loadgen.py`,
фоновые проверки HTTP-кодов. Воспроизведение сценариев — `scripts/chaos.sh`
(шаги приведены там же).

F1, F5 и F6 замерялись 2026-11-08 по текущей методике и актуальному коду
(нагрузка, коды, LAG и сверка с ClickHouse в табличных полях). F2, F3, F4, F7
замерялись раньше, на прогоне этой же конфигурации стенда; числа помечены
датой. Важно при воспроизведении: образы собираются из локальных
`*/target/*.jar` — перед `docker compose build` обязателен
`mvn package -DskipTests`, иначе в контейнеры попадает старый jar.

## Находки



1. **Read-путь fail-fast**: TimeLimiter + CircuitBreaker на
   `UserReadService` дают честную деградацию — подтверждено F5: первый ответ
   ~3 с, далее ~60 мс до восстановления зависимости.
2. **Приём метрик не зависит от доступности Kafka** (гарантия «не меньше
   одной доставки»): 202 фиксирует запись в outbox PostgreSQL, доставчик
   добирает события после возврата брокера — подтверждено F6 (0 ошибок
   клиента при 30 с отсутствия Kafka; без потерь и дублей).
3. Топология стенда: `kafka1`,`kafka2` — брокеры с копиями топиков, `kafka3`
   controller-only (копий не хранит). При RF2/`min.insync.replicas=2` отказ
   любого из двух брокеров останавливает **новую** запись в топики `metrics`/
   `incidents` (недостаточно синхронных реплик); чтение и доставка
   накопленного продолжаются, кворум контроллеров жив. Отказ `kafka3` на
   запись не влияет. Для прода — RF≥3/`acks=all`/`min.insync=2` и брокеры на
   разных узлах (предложение в `docs/decisions.md`).
4. nginx `proxy_next_upstream ... non_idempotent` + стабильный
   Idempotency-Key: при убирании реплики клиент не видит ошибок (F1).

5. **Яды в топике `incidents`**: нечитаемое событие (битый JSON или не-UUID в
   `userId`) оставляет consumer в бесконечном ретрае (`DefaultErrorHandler`,
   `UNLIMITED_ATTEMPTS`) и блокирует партицию до вмешательства — в эксперименте
   record удалён через `kafka-delete-records`. Политика отказа/Dead-Letter для
   ядов в DEMO не реализована, вынесена владельцу (`docs/decisions.md`).
