# Fault injection (Этап 8)

Стенд: compose-кластер (см. README «Целевая система»), нагрузка `loadgen.py`,
фоновые проверки HTTP-кодов. Воспроизведение сценариев — `scripts/chaos.sh`
(шаги приведены там же).

Перезапуск 2026-11-08 на коде после P0-1/P0-2/fast-fail: **F1, F5, F6** —
актуальные результаты в таблице. F2, F3, F4, F7 на этом стенде не перезапускались
и остаются ИСТОРИЧЕСКИМИ результатами Этапа 8 (до outbox-изменений); их выводы
по независимости путей в силе, но числа требуют подтверждения на актуальном коде.
Важно при воспроизведении: образы собираются из локальных `*/target/*.jar` —
перед `docker compose build` обязателен `mvn package -DskipTests`, иначе в
контейнеры попадает старый jar (проверено: молча едет старая логика).

## Находки

1. **Read-путь не fail-fast** — ИСПРАВЛЕНО, подтверждено перезапуском F5
   2026-11-08: TimeLimiter + CircuitBreaker на read-пути, первый запрос
   ~3 с, далее 503 за ~60 мс, зависаний нет. (История: раньше GET с мёртвой
   зависимостью висел ≥15 с; частично смягчалось JDBC/Hikari таймаутами.)
2. **Раньше: 503 при приёме — не потеря данных.** После P0-2 неактуально:
   приём вообще не зависит от доступности Kafka (202 = записано в outbox
   PostgreSQL), доставка догоняется отправителем — подтверждено F6
   (2026-11-08): 30 с отказа kafka1, 0 ошибок клиента, доставка за ~6 с,
   ни потерь, ни дублей.
3. Топология стенда: `kafka1`,`kafka2` — брокеры с копиями топиков, `kafka3`
   controller-only (копий не хранит). При RF2/`min.insync.replicas=2` отказ
   любого из двух брокеров останавливает **новую** запись в топики `metrics`/
   `incidents` (недостаточно синхронных реплик, F6); чтение и доставка
   накопленного продолжаются, кластер управления живёт (2 из 3 контроллеров).
   Отказ `kafka3` на запись не влияет вовсе. Для прода — RF≥3/`acks=all`/
   `min.insync=2` и брокеры на разных узлах (см. предложение в `docs/decisions.md`).
4. Настройка nginx `proxy_next_upstream ... non_idempotent` закрыла обрывы
   соединений при убирании копии сервиса — ошибка Этапа 7 (32 из 3157) на F1
   не повторилась (0 ошибок).
